## Release evidence rule

A source reference can justify an architecture decision, but it does not prove the control exists. Release evidence is accepted only from one exact candidate identity. `RELEASE.md` and `.github/workflows/release.yml` require the tag version, Cargo version, dated changelog, protected `main` tip, repository verification, complete statement/branch coverage, positive LSM-capable real runtime acceptance, byte-reproducible Cargo package, SPDX SBOM, checksums, release-evidence manifest, and GitHub attestations to converge on the same source/package identity.

Queued, skipped, cancelled, stale, predecessor-head or LSM-unavailable evidence remains non-passing. Command-plan tests are never cited as proof that real isolation succeeded.
