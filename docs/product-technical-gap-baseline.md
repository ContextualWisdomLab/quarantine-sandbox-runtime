## Artifact analysis

The active foundation keeps SHA-256 artifact identity, bounded ingestion, deterministic format classification/evidence ordering, analyzer failure attribution, and no execution in static paths under `src/artifact_analysis/`. Draft #18 owns issue #17's Claude-plugin package-analysis contract RED and issue #49's analyzer-worker isolation RED while preserving quarantine-sandbox-runtime as evidence/isolation owner; AppGuardrail remains static-scan/SARIF authority, Noema remains admission/activation authority, and Wardnet remains verdict/incident authority.

Issue #49 is a P0 artifact-analyzer isolation/evidence boundary. Current `AnalysisEngine::analyze_bytes` invokes arbitrary public `StaticAnalyzer` trait objects directly in the runtime host process and later publishes policy/runtime evidence that no network access, credential availability, or dynamic execution occurred. That claim is not enforceable against the already-modeled compromised-analyzer adversary. Test-bearing `d67e16a241335b3d3ecd4e37cc80d9efc5200342` attempts a loopback TCP connection from an otherwise-valid static analyzer and requires the runtime-host connection not to succeed. The checked-in RED permits fail-closed rejection before unsafe analyzer invocation or execution behind an enforceable capability-denying worker; it forbids treating the in-process trait call itself as an isolation boundary. ADR-0009 remains Proposed and `docs/doctoring/ARTIFACT_ANALYZER_ISOLATION_TRACEABILITY.md` records the NIST SP 800-190/Rust process-capability evidence chain.

Issue #50 and Draft #51 separately close the worker-to-controller resource-isolation gap. `StaticAnalyzer::analyze` currently hands the controller an already-materialized `Vec<AnalyzerFinding>`, and the engine accumulates all findings before aggregate validation. Test-bearing `618f3dae4fa7909a8725ab67895375abebba6339` amplifies one small immutable artifact into 512 individually valid findings against issue #17's versioned 65,536-byte output-budget fixture and forbids an over-budget aggregate from becoming `Completed` evidence. The eventual GREEN must enforce versioned byte/count budgets while reading/framing/normalizing worker output, terminate and clean the exact worker on overflow, and never present truncation as completeness. A larger controller heap or post-hoc validation of an attacker-sized vector is not resource isolation.

Issue #52 and Draft #53 close coupled evidence-contract contradictions. `AnalysisProfile` exposes Linux/Windows dynamic profiles and `EvidenceKind` exposes `RuntimeBehavior`, but current validation rejects every `dynamic_execution_performed=true` manifest while also failing to cross-bind requested profile, execution fact, completeness, and observed-runtime evidence. Initial test-bearing `4cc901d7cb40bdc833e08b0c695ba12c27fa2f68` requires truthful completed Linux/Windows dynamic receipts to be representable while preserving `StaticOnly + dynamic_execution_performed=true` as invalid. Rust hardening `7fa9116a993d6854ad579db2512ff921edcb8611` requires unavailable dynamic execution to remain `false + Inconclusive`; wire hardening `bb1001016f3efd3183fb903cdde242f0859279e5` and executable schema semantics `e0ddf5abf96ff50718491ec4c59bb3728a71eed9` require equivalent JSON Schema behavior; latest test-bearing `2b540a0a2c24c7e53c183ff2a8ea1e85cd30daa8` rejects `RuntimeBehavior` when execution did not occur. The smallest causal GREEN is a version-compatible Rust/schema contract repair. It must not implement a fake worker, weaken StaticOnly, or turn unavailable execution into `Completed`.

Issue #54 and Draft #55 close the analyzer-provenance identity gap. The public analyzer contract exposes a human-readable `analyzer_id()` but current deterministic job and normalized producer identity do not bind immutable implementation/version/digest/configuration provenance. Initial RED `06ee0a1264960843a8ecd93d0e5ecff247866b17` proves two implementations sharing one display ID can emit different evidence under one job identity; `87f579311e992a5815e7887e83e050598d23902d` preserves repeat determinism; `c32c2c489356213e70360087851b6c08df855c61` prevents result hashes or job-only differentiation from masquerading as producer provenance; `671b81dfca03ba345c8a5b01d93edffbc79995ac` keeps stable-provenance admission symmetric and fail closed before analyzer/worker invocation without forcing one constructor shape. The future GREEN must bind stable versioned analyzer artifact/package, semantic-version/configuration, and exact-worker provenance into deterministic job and serialized producer/worker evidence. Random UUIDs, process identity, paths, result hashes, Rust `TypeId`, or overloaded runtime source revision are not release provenance.

Issue #56 and Draft #57 close a separate false-completeness path. `RuntimeDisposition::Completed` means every analyzer required by the profile completed, while `EvidenceKind::ToolFailure` records attributable analyzer/worker failure. Current bundle validation and checked-in schema allow those two facts to coexist. RED `c95c74f415180bd321c0197a69499e569ad27f21` requires `ToolFailure + Inconclusive` to remain representable while rejecting `ToolFailure + Completed`; schema-semantics hardening `355a64d908f9199adbe472b54fda65f7e69ba7f3` evaluates representative Draft 2020-12 applicator/assertion behavior instead of keyword presence. The future GREEN must keep partial failure evidence without normalizing it into a completed runtime-owned receipt.

YARA-X/capa/Ghidra/LIEF adapters, dynamic Linux/Windows detonation, durable signed evidence, and immutable analyzer implementation/configuration provenance remain missing commercial slices. New analyzers must execute behind or strengthen the Core sandbox boundary rather than parse hostile artifacts with runtime-host network/environment/filesystem/process authority. Static evidence is not observed runtime behavior; worker isolation does not make an unbounded result channel safe; a dynamic receipt must not understate or fabricate execution; a display ID is not executable provenance; and analyzer/worker failure cannot be normalized into `Completed`.
